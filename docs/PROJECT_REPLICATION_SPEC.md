# 基本面排雷 Agent —— 项目复刻规格书（给 AI）

> **2026-09-09 当前版本更新：V1.3**。报告/规则版本 1.3，60 项检查，新增 8 项深度检查、重叠评分合并与原始响应/审核底稿追溯。用户已授权升级原 52 项基线；下文涉及 V1.2、规则 1.1、固定 52 项及原测试数字的内容为历史记录。当前行为和限制以 [V1.3 升级说明](V1.3_RULE_UPGRADE.md) 为准。

> 本文档是**给 AI 的完整项目生成规格**。请 AI 据此从零实现一个 A 股 / 港股基本面排雷 Agent。
> 目标：输入股票名称或代码，自动检索财报与公告，由**程序**计算指标并执行规则，输出一份
> 每条结论都绑定到具体披露文件与页码的离线 HTML 风险报告。
>
> 阅读与执行约定：本文按「原则 → 架构 → 数据源 → 规则 → 报告 → 验收」组织，规则与误报治理
> 部分是项目的核心资产，必须原样实现；不得擅自增删规则、改阈值、或让模型参与数值计算。

## 一、一句话定位

**输入一只股票，告诉你它哪里可能藏雷，每条都带原文证据。**

输出物：一份可在线查看、可下载离线阅读的 HTML 报告（内联 CSS + 内联 SVG，零外部资源）。

## 二、不可违反的产品原则（最高优先级）

以下原则优先于任何实现便利，AI 不得违反：

1. **模型不参与任何数值计算**。所有指标由程序计算；LLM 只做「解释已算出的异常」与「结论—证据一致性核验」。未配置密钥时相关步骤整体跳过并在报告中标注，绝不伪造结论。
2. **每条风险结论必须有可回溯来源**：绑定到具体披露文件 + 页码 + 内容指纹；报告生成后程序做一次原文复核（重新打开 PDF 比对指纹），复核未通过的在报告中标注。
3. **数据不足显式呈现**：缺少必需科目或公告时输出「数据不足，无法判断」，不硬造结论、不输出「未发现异常」。
4. **不输出投资建议、爆雷概率、公司评级**。风险信号评分只是「检查项扣分加权汇总」，报告内附免责行。
5. **严重程度、证据强度、时效三者分开表达**，不混成一个分数。
6. **在线、下载、JSON、数据库同一事实源**：`data/reports/{task_id}.json` 是唯一事实源，HTML 由它渲染，在线与下载用同一模板，内容逐字节一致。
7. **动态内容统一转义**（防 XSS），来源链接仅允许 http/https 协议（防 `javascript:` 注入），下载器默认禁止内网地址（防 SSRF）。
8. **不得通过减少材料来提速**。可并行、可缓存，但不得少抓公告、少解析 PDF。
9. **旧报告兼容**：历史 JSON 缺新字段时给默认值，旧报告仍可渲染，不报错。
10. **不得为通过测试而修改测试期望**；测试必须真实覆盖边界样本。

## 三、技术栈与架构

| 项 | 选型 |
|---|---|
| 语言 | Python 3.12+ |
| Web 框架 | FastAPI + Uvicorn（本地单机，`127.0.0.1:8770`） |
| 存储 | SQLite（单文件），`CREATE TABLE IF NOT EXISTS` + `ALTER ADD COLUMN` 幂等迁移 |
| 报告模板 | Jinja2（`StrictUndefined`，未定义变量直接报错而非渲染空白） |
| PDF 解析 | pdfplumber |
| LLM | 任意 OpenAI 兼容协议（DeepSeek / 智谱 GLM / Kimi / 通义千问等），可插拔 |
| HTTP | 标准库 `urllib`，自实现：每主机限流、指数退避重试、体积上限、SSRF 防护、全程留痕 |

**八阶段主流程**（固定顺序，不可乱）：

```
公司识别 → 检索规划 → 资料获取 → 标准化 → 规则检查 → 专项阅读 → 核验 → 报告生成
```

**关键架构决策（必须遵守）**：

- 指标全部程序计算，LLM 只解释（消除模型算错数的风险）。
- 独立模型批次最多 2 路并行，按输入顺序合并；不改变输入、参数、预算、校验和合并顺序。
- 评分在渲染层计算，历史 JSON 无需迁移即可重渲染出新评分。
- 规则引擎采用「配置化规则」：每条规则 = 触发条件 + 阈值 + 适用/排除行业，用函数实现。
- 后台任务用进程内线程池（上限 5 并行）。

## 五、数据源（公开接口，无鉴权）

| 数据 | 来源 | 说明 |
|---|---|---|
| A股/港股财报 + 主要指标 | 东方财富数据中心公开接口 | 三张报表 + 主要指标，含公告日期、报告期类型 |
| A股公告 + PDF | 巨潮资讯网 cninfo.com.cn | 深交所法定披露平台 |
| 港股公告 + PDF | 港交所披露易 hkexnews.hk | 公开网页接口（非 IIS 授权信息流） |
| 公司资料 | 东方财富 F10 | 全称、行业、审计机构、实际控制人、曾用名 |

**数据源踩坑经验（必须实现，否则会踩同样的坑）**：

1. 巨潮 `orgId` 构造规则不统一（如 `gssh0600519` / `gssz0000001`），**必须走 `topSearch` 接口解析**，不能按规则拼接。
2. 披露易 `titleSearchServlet` 的 `page`/`startRow` 参数**无效**，分页靠**时间窗口二分**实现全量取回。
3. 港股披露为**繁体中文**，证据定位需要简繁双字形比对。
4. 对公开数据源保持克制：**每主机限流 2 rps**，超频会被限流。
5. 商用授权未确认，公开部署前需与数据方核实（写入已知限制）。

## 六、财务标准化与指标计算

- 财务事实落库字段：原始科目 + 标准科目、币种、单位、报告期类型（季/中/三/年）、累计口径、审计标记、来源 URL。
- **指标计算的边界处理（必须）**：
  - 零分母 / 缺失 → `None`，绝不产出 `inf`/`nan`。
  - 负利润不套用普通同比（返回 None 并说明）。
  - 同比严格同口径（中报对中报），要求币种、范围、单位、期间一致。
  - 受限资金从可用现金中扣除；缺失不能当零。
  - 港股单列现金及等价物，不再次扣除受限现金。
- **重要性过滤**：应收账款、存货占总资产 < 2% 时，其增速类指标不形成结论（小基数增速无经济意义）。

## 七、规则引擎（52 项，核心资产，必须原样实现）

规则按「五档结论」输出：**发现风险 / 需要关注 / 已覆盖资料中未发现明显异常 / 数据不足，无法判断 / 不适用**。
严重程度（高/中/低/未定）与证据强度分别表达。

行业包路由：按行业分类关键词匹配（银行/保险/券商/地产），无法判定归 general；
特殊行业在行业包之外仍执行财务质量、治理、监管类通用规则。

| ID | 名称 | 判定逻辑与阈值 |
|---|---|---|
| RE01 | 剔除预收后的资产负债率 | (总负债−预收−合同负债)/(总资产−预收−合同负债) >70% 风险(高)；>60% 关注(中)；替代 SV02 |
| RE02 | 可动用现金对短债覆盖 | (货币资金−受限资金)/短期借款 <1 风险(高)；<1.5 关注(中) |

| RE04 | 预收款项变动 | 预收款项较上期下降 >30% 关注(中) |

**能力口径（`Capability`）**：`enabled`（具备可靠数据字段）与 `unsupported_source`（数据源暂不支持）。
`unsupported_source` 的检查**不计入「已执行的有效检查数量」**，仅在「尚缺数据能力」区展示，
不冒充已完成检查、也不冒充数据不足。判断顺序：**不适用（NOT_APPLICABLE）优先于能力状态**。

### 7.3 误报治理（必须有测试回归保护）

以下误报必须修复并用单元测试锁定，否则会重蹈覆辙：

1. 财务费用为负（利息净收入）时利息保障倍数无经济意义 → SV04 先判符号。
2. 半年报固定勾选项「□适用 √不适用」命中「保留意见」关键词 → OP02 断言式匹配 + 模板排除 + 否定词识别 + 区间去重。
3. 续聘/履职评估公告被当成审计机构变更 → GV01 区分变更词（改聘/更换）与例行词（续聘/履职评估）。
4. 小基数存货/应收增速误报 → FQ03/FQ05 重要性门槛（<2% 总资产不结论）。
5. 港股例行文件被误分类为高管变动 → 披露易分类器先识别例行文件。
6. 行业包启用导致通用规则全部跳过 → 白名单改为 exclude_packs 排除制。

## 八、评分与覆盖

**风险信号评分**：基础 100，按检查项扣分——发现风险 高-12/中-8/低-4，需要关注 中-2/低-1，下限 0；
「数据不足」「不适用」「数据源暂不支持」不扣分。评分为检查项扣分加权汇总，反映风险信号密度，
不代表投资价值或违约概率。可附带 A—E 档位（A≥95/B≥80/C≥60/D≥35/E<35），但**不作为公司评级**。

**覆盖等级**（与任务状态分离）：

| 概念 | 值 |
|---|---|
| 任务状态 | 排队 / 运行 / 生成成功 / 超时 / 生成失败 / 取消（表达「是否成功生成」） |
| 覆盖等级 | 完整 / 一般缺口 / 关键缺口（表达「数据覆盖缺口严重度」） |

**缺口（gap）**：扫描中每个「本该覆盖但没覆盖全」的地方记录一条文字。
关键缺口关键词：`未获取到任何财务报告期数据`、`财务数据获取未完成`、`停止财务数据请求`、
`公告获取未完成`、`公告获取未执行`、`无法在巨潮定位`、`无法在披露易定位`。
存在任一关键缺口 → 关键缺口；仅有一般缺口 → 一般缺口；无缺口 → 完整。

## 九、事件与生命周期

**事件分类（固定枚举，模型候选只能用这些，其他拒收）**：
监管处罚、监管调查、诉讼、资产冻结、监管问询、上市地位、财务更正、盈利警告、审计机构、
股权质押、担保、关联交易、高管变动、股东减持、质押冻结。

**AI 候选事件与正式事件分层**：模型只产候选（doc_id + 证据片段），程序据此定位完整引文、
生成 Evidence 并做原文复核；复核通过升级为正式事件，未通过进「待核实线索」区（不参与风险计数）。

**事件生命周期**：同一事项多份披露用确定性关联键去重（**案件号 > 公告编号 > 标题核心关键词**）。
「已解除」必须由日期更晚、关联键一致、且标题命中该类别解除关键词的后续正式披露支撑；
时间经过或模型判断不构成解除依据。历史追溯仅对未解除的重要事件按需启动，受查询/公告/下载/耗时上限约束。

## 十、报告结构（4 节）

标题格式：`证券简称（代码）排雷报告`，如「兆易创新（603986.SH）排雷报告」。

1. **风险总览**：执行摘要条（最高已确认风险 / 风险·关注数 / 有效覆盖率 / 证据复核率 / 覆盖等级）+ 风险信号评分 + 发现清单（索引，点击跳转第 3 节）。
2. **逐项检查结果**：五维度逐条结论；「不适用」「数据不足」「数据源暂不支持」行默认不显示（JSON 数据层完整保留）。
3. **问题详情与原文**：每条结论的完整证据链（原文片段 + 页码 + 指纹），原始证据默认折叠，打印时自动展开。
4. **数据来源与算法**：AI 参与情况、计算口径、缺口清单、免责声明。

**格式硬要求**：内联 CSS + 内联 SVG，0 外部脚本/字体/图片，离线可读可打印；动态文字转义；
链接仅 http/https；手机端将宽表转换为带字段标签的卡片（不横向滚动）。

## 十三、LLM 接入踩坑（必须实现）

- 思考/推理模型（如 GLM）的推理内容计入 `completion_tokens`，`max_tokens` 会截断 JSON：
  识别 `finish_reason=length`，`interpret_anomalies`/`extract_events` **分批调用**（每批少量），单批失败只丢该批。
- 单次扫描模型预算超出自动降级为「未启用」，并如实上报 failures（写入缺口）。
- 未配置密钥：AI 解读/核验整体跳过并标注，其余流程照常。

## 十四、测试与验收标准

**测试必须离线、确定性**（不依赖网络与密钥），覆盖：

- 报告渲染：标题格式、无「未发现异常」残留、评分块、离线自包含（0 外部资源）。

**端到端验收样本**（真实接口，人工复核）：

## 附：关键实现注意点汇总

- 评分在渲染层算，历史 JSON 可重渲染出新评分。
- 证据带内容指纹 + 事后复核，防止「引用不存在的原文」。
- 渲染层用 `rejectattr` 过滤「不适用/数据不足」行，但 JSON 完整保留 52 项结果。
- SQLite 幂等迁移，历史行未知字段保持 NULL，不伪造审计/口径属性。
- 内容寻址存储（SHA256 硬链接去重）避免重复下载同一 PDF。
- 提供安全清理命令（默认只预览，`--execute` 才删缓存/旧报告版本行）。
