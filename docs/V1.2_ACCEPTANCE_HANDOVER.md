### 3.1 事件证据绑定核查（完成定义 #4）

`timeline` 中的事件分两类，**只有 `evt:ai:*` 前缀属于「AI 候选事件升级的正式事件」**，
须满足「绑定至少一条通过复核的证据」；`evt:cninfo:*` 是程序确定性路径直接关联公告
（公告本身即事实源，绑定 `source_doc_id`），不适用该条。用以下脚本验证：

```bash
python - <<'PY'
import json
for tid in ['158a87c9e479','58a997248cf9','e2ac0b68d20a']:
    d = json.load(open(f'data/reports/{tid}.json'))
    tl = d.get('timeline', [])
    ai = [e for e in tl if str(e.get('event_id','')).startswith('evt:ai')]
    ai_no_ev = [e for e in ai if not e.get('evidence_ids')]
    print(tid, 'AI事件', len(ai), '无证据', len(ai_no_ev))
PY
```

预期输出：三行「AI事件 N 无证据 0」。

## 七、接口变化

- **任务状态**：旧「完成/部分完成/失败」不再写入；新值 排队/运行/生成成功/超时/生成失败/取消；历史行经 `display_status()` 兼容映射。
- **覆盖等级**：完整/一般缺口/关键缺口。
- **报告 payload 新增**：`scan.coverage_level`、`summary.unsupported_count`、`unsupported_data`、`capability_summary`、`rules[].capability`、`timeline[].lifecycle_stage` 等。
- **管理页 `/admin`** 新增「缓存命中率」「阶段耗时」。

## 九、已知限制（验收时不应视为缺陷）

1. 数据源为公开网页接口（东财/巨潮/披露易），商用授权未确认，公开部署前需与数据方核实。
2. 历史报告 JSON 中部分 `security.name` 仍为代码（新生成的不受影响）。
3. 按需历史追溯受资源上限约束（查询/公告/下载/耗时），超限记录缺口而非静默省略。
4. `data/publish/` 外部分享流程未自动化；本地版以线程池 + SQLite 等价实现，运行中任务断点续跑未做。
5. 单次扫描耗时受数据源文件体积影响（例如 15MB+ 年报会显著拉长资料获取阶段），非缺陷，属公开源客观约束。
