## 评分与覆盖率

新报告使用 `scoring_version=2`。以下重叠检查按组内最高扣分计入，原始结论和风险项计数保留：

- FQ01/FQ02/FQ13：利润现金匹配。
- SV01/RE02/SV10：短期现金覆盖。
- OP02 与明确引用“审计报告披露持续经营”的 OP05：审计持续经营；OP05 单独的双负或负权益信号不强行并入。

这是有限、显式的检查组去重，不声称已经完成所有诉讼、担保、关联交易的事项级去重。报告显示合并组及实际计入项目。旧 JSON 未携带新评分版本时仍用旧算法，避免历史报告分数静默改变。

原有效覆盖率保留；额外显示 `evaluated / (applicable + unsupported)` 的整体检查覆盖率，避免有效覆盖率 100% 被误解为全部能力齐全。资料缺口不通过降低风险扣分来补偿。

## 原始资料与审核底稿

沿用项目目录，不覆盖历史数据：

1. 数据来源：东方财富公开接口、巨潮/披露易原始 PDF；模型请求和密钥不进入快照。
2. Raw：新的东方财富请求在映射前按 SHA-256 保存解码后的原始 JSON 响应到 `data/raw/eastmoney/`，同内容复用；请求参数、提取时间和映射版本记录到 `data/source_manifest/`。PDF 沿用 `data/files/` 原文存储。
3. 底稿：`FinancialFact.raw_ref` 链接 Raw 响应，SQLite 以兼容迁移新增字段；每条结果记录初始状态、规则版本、所需指标。新增规则进一步记录逐期输入、公式、阈值、缺失字段，或原文页码、命中、排除理由。
4. 最终结果：报告 JSON 中 `rule_workpapers`、`raw_snapshot_refs` 与 SQLite `rule_results.metric_snapshot` 保留底稿；HTML 提供折叠查看。

历史数据没有 Raw 响应链接时保持为空，不能伪造历史原始响应。解析页段不足、主体不明确、表格无法可靠提取时写明数据不足。原始快照属于追溯资料，不应按普通缓存自动清理。
