## 一、最终行为（用户可见变化）

V1.2 在**不增加规则数量、不降低报告质量**的前提下，提升报告可信度与可复核性。核心变化：

1. **模型结果可复现**：模型调用结果按（供应商/模型/温度/推理配置/输出上限/提示词哈希/版本/业务步骤/校验版本）
   组合键缓存；同一输入二次扫描直接命中缓存，失败响应不污染缓存；同键并发去重。
2. **AI 事件与正式事件分层**：模型只产出候选事件（doc_id + 证据片段），程序据此定位完整引文、
   生成 Evidence 并做原文复核；复核通过才升级为正式事件，未通过进入「待核实线索」，不进入结论。
3. **事件生命周期与按需追溯**：同一事项以确定性关联键（案件号 > 公告编号 > 标题关键词）去重；
   解除须有后续正式披露依据；进展不重复计数；对未解除的重要事件按需向前追溯历史公告。
4. **任务状态与覆盖等级分离**：任务状态（排队/运行/生成成功/超时/生成失败/取消）表达「是否成功生成」；
   覆盖等级（完整/一般缺口/关键缺口）单独表达「数据覆盖缺口严重度」。
5. **评分表达调整**：保留醒目的 A—E 风险等级徽章（A 绿 / B 蓝 / C 黄 / D 橙 / E 红），
   便于用户快速查看；同时展示最高已确认风险、风险关注数量、有效覆盖率与证据复核率。
6. **资料选择与目标章节**：披露文件按类别配额选择（重要类别不被例行公告挤出）；
   PDF 解析缓存（SHA256 + 解析器版本 + 页数 + 起始页）；长文档目标章节定向补充解析。
7. **行业规则能力口径**：银行/保险/券商监管类检查（资本充足率、偿付能力、净资本等）
   数据源未提供字段时标记「数据源暂不支持（unsupported_source）」，不计入已执行有效检查数量。
8. **运行诊断与存储控制**：`stage_timings` 记录八阶段耗时；`runtime_stats` 记录缓存命中率；
   内容指纹去重（SHA256 硬链接 blob）；提供安全清理命令。

上述行为均保持产品原则：模型不参与财务计算、风险结论可回溯、数据不足显式呈现、
不输出投资建议/爆雷概率；A—E 仅表示规则触发后的风险信号分档，严重度/证据强度/时效分开表达、在线/下载/JSON 同一事实源、
动态内容转义、旧报告兼容。

## 二、数据库迁移

SQLite 迁移在 `app/core/db.py: init_db()` 中自动执行（启动时），无需手工迁移脚本。
`CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ADD COLUMN` 幂等，历史数据保留、未知字段保持 NULL。

**新增表：**

| 表 | 用途 |
|---|---|
| `llm_cache` | 模型结果缓存（cache_key 主键 + payload + created_at） |
| `stage_timings` | 八阶段耗时与摘要（task_id/stage/stage_index/started_at/ended_at/elapsed_ms/summary） |
| `runtime_stats` | 运行时统计（key/value：缓存命中/未命中计数等） |

**已有表新增列（向后兼容，历史行不伪造）：**

| 表 | 新增列 |
|---|---|
| `scan_tasks` | `coverage_level`（覆盖等级） |
| `financial_facts` | `period_start`、`audited`、`consolidated` |
| `fetch_logs` | `record_id`（+ 唯一索引 `idx_fetch_record`） |
| `risk_events` | `dedup_key`、`occurrence_order`、`lifecycle_stage`、`related_doc_ids`、`resolution_basis`、`resolution_date` |

**新增内容寻址存储**：`app/core/storage.py` 的 `blob_path(sha256)` + `dedup(path, sha256)`，
以硬链接去重重复下载的同一 PDF 内容，失败时退回原路径。

## 三、接口变化

**任务状态（`TaskStatus`）**：旧「完成 / 部分完成 / 失败」不再作为新任务写入；
新状态为 排队 / 运行 / 生成成功 / 超时 / 生成失败 / 取消。历史行保留原值，
展示时通过 `display_status()` 映射为 V1.2 口径（旧「完成/部分完成」→「生成成功」）。

**覆盖等级（`CoverageLevel`）**：完整 / 一般缺口 / 关键缺口，由缺口列表经 `classify_gap()` 推导。

**报告 payload 新增字段：**

| 字段 | 说明 |
|---|---|
| `summary.unsupported_count` | 数据源暂不支持的行业检查数 |
| `scan.coverage_level` | 覆盖等级 |
| `unsupported_data` | 数据源暂不支持的检查明细（rule_id/name/dimension/reason） |
| `capability_summary` | 行业规则能力摘要（enabled / unsupported_source / unsupported_rules） |
| `rules[].capability` | 每条规则的能力状态（enabled / unsupported_source） |
| `timeline[].lifecycle_stage` 等 | 事件生命周期字段 |

**管理页 `/admin`** 新增「缓存命中率」「阶段耗时」卡片。

## 六、性能结果

- 模型结果缓存与 PDF 页段缓存均保持完整输入；成功解析的长 PDF 截断页段现在也会缓存，并通过原子写入避免并发半文件。
- 事件抽取使用至少 8,000 输出 token，解决真实样本在 4,000 上限下被思考 token 截断的问题；最终三份样本模型截断缺口均为 0。
- 最终腾讯为 30.2s，相较交接基线 51.3s 缩短 41.1%；中间缓存复测曾达到 25.3s。
- 茅台 69.5s（原 169.4s，缩短 59.0%）；万科 69.4s（原 123.8s，缩短 43.9%）。
- 缓存命中率与阶段耗时已在 `/admin` 页可视化。
- 未通过减少材料来提速；扫描耗时主要由「资料获取 + 专项阅读（模型批次）」构成，
  与 V1.1 基线一致，V1.2 未引入额外串行开销。

## 七、剩余限制

1. 数据源为公开网页接口，商用授权未确认，公开部署前需与数据方核实。
2. 历史报告 JSON 中部分 `security.name` 仍为代码（新生成的不受影响）。
3. 按需历史追溯受资源上限约束（查询/公告/下载/耗时），超限记录缺口而非静默省略。
4. `data/publish/`（外部分享链接）为手工发布流程，未自动化。
5. 本地版以线程池 + SQLite 等价实现；运行中任务的断点续跑未做。
6. 最终验收后的本地公告 PDF 与解析缓存已清理以控制仓库工作目录体积；首次新扫描会按需重新下载。

## 九、回滚方法

V1.2 改动均在 `v1.2` 分支，`main` 分支保持在 V1.2 开发前的 `addf053`（V1.1 状态）。

**代码回滚**（任选其一）：

```bash
# 方式 1：切换回 main 分支（V1.1 完整状态）
git checkout main

# 方式 2：在 v1.2 分支回退到指定提交
git checkout v1.2
git revert <commit>            # 逐提交回退，或
git reset --hard <commit>      # 硬回退（丢弃后续提交）
```

**数据回滚**：数据库迁移均为幂等 `ADD COLUMN`，历史数据未被改写或删除；
回滚代码后旧数据仍可读（新增列/表被忽略）。清理命令默认只预览、加 `--execute` 才实际删除，
删除前会保留报告 JSON 事实源。
