# A 股 / 港股基本面排雷 Agent

输入股票名称或代码，系统识别公司，检索最新财报与公告，程序计算指标，
输出有原始证据、可下载离线阅读的 HTML 风险报告。

当前**报告版本为 V1.2（可信度改造）**，规则版本保持 **1.1**（52 项规则与阈值不变）。
V1.2 在不增加规则数量、不降低报告质量的前提下，新增：模型结果缓存与可复现、AI 候选事件分层、
事件生命周期与按需历史追溯、任务状态与覆盖等级分离、资料选择与目标章节解析、行业规则能力口径、
运行诊断与存储清理。累计 **261 项自动测试通过**（58 项原有确定性测试 + 203 项验收回归与边界测试）。
旧版报告仍可查看，但须重新扫描才能应用 V1.2 口径。详细变更见 [实施报告](docs/V1.2_IMPLEMENTATION_REPORT.md)。

- 市场：沪市、深市、北交所、港股上市公司（基金/ETF/债券不进入扫描）
- 扫描：财务质量、偿债能力、公司治理、监管法律、经营行业五个维度
- 时间范围：最近 5 个完整财年 + 最新已披露财报 + 近 12 个月公告
- 行业适配：通用规则 + 银行、保险、券商、地产行业规则包
- 结论：每条绑定到具体披露文件与页码，数据不足的项明确标注，不输出"未发现异常"
- 不输出爆雷概率，不构成投资建议；报告提供**风险信号评分**（检查项扣分加权汇总，
  反映风险信号密度，不代表投资价值或违约概率）。报告保留醒目的 A—E 风险等级徽章，
  便于快速查看；同时展示最高已确认风险、风险关注数量、有效覆盖率与证据复核率

## 快速开始

```bash
# 1. 安装依赖（Python 3.12+）
pip install -r requirements.txt

# 2.（可选）配置模型：复制 .env.example 为 .env，填入 LLM_API_KEY
#    不配置也能完整运行，AI 解读步骤会自动跳过并在报告中标注

# 3. 启动
python -m uvicorn app.main:app --host 127.0.0.1 --port 8770

# 4. 打开 http://127.0.0.1:8770
```

停止服务：如果服务在当前终端前台运行，按 `Ctrl+C`。如果它在后台运行，可按监听端口找到进程并正常停止：

```bash
PID=$(lsof -tiTCP:8770 -sTCP:LISTEN)
if [ -n "$PID" ]; then kill "$PID"; fi
```

命令行方式（不启动 Web）：

```bash
python scripts/run_scan.py 600519        # A 股：贵州茅台
python scripts/run_scan.py 00700         # 港股：腾讯控股
python scripts/run_scan.py 000002.SZ     # 显式证券代码，避免歧义
```

测试（共 261 项，全部离线，不需要网络与密钥）：

```bash
python tests/run_tests.py                                      # 原有确定性测试：58 项
python -m unittest discover -s tests -p 'test_*.py' -v         # 验收回归与边界测试：203 项
```

清理缓存与历史报告版本（安全，默认只预览，加 `--execute` 才实际删除）：

```bash
python scripts/cleanup.py              # 预览将删除的内容
python scripts/cleanup.py --execute    # 实际清理 PDF 解析缓存、模型缓存、旧报告版本行
```

### 释放本地磁盘空间

公告 PDF、PDF 解析缓存和验收过程的 `runtime/` 目录均为可再生文件。确认当前没有扫描任务后，
可删除这些内容；下次强制扫描会按需重新下载公告原文：

```bash
rm -rf data/files data/cache/pdf_parse \
  docs/acceptance-2026-09-06/runtime docs/fixes-2026-09-06/runtime
```

`data/reports/` 中的 HTML/JSON 是本地导出副本；Web 报告以 `data/app.db` 中的报告 payload 为事实源，
不需要离线副本时可以删除旧文件。不要删除 `data/app.db`，除非明确要清空全部任务、报告和模型缓存。

2026-09-06 完成过一次清理：删除上述临时目录、全部可重下 PDF、解析缓存和 62 个旧报告文件，
保留最终三份 V1.2 报告；项目占用由约 601 MB 降至 43 MB。清理后首次扫描会重新下载 PDF，
因此首次耗时可能高于已命中本地文件缓存的复测结果。

## 配置

所有配置通过环境变量或 `.env` 文件读取，全部有安全默认值，零配置可运行。
完整清单见 `.env.example`，常用项摘要：

| 配置 | 默认 | 说明 |
|---|---|---|
| `LLM_API_KEY` | 空 | 模型密钥。不配置则 AI 解读/核验整体跳过并标注 |
| `LLM_BASE_URL` / `LLM_MODEL` | DeepSeek | 任意 OpenAI 兼容服务商均可 |
| `LLM_BUDGET_CNY` | 3.0 | 单次扫描模型预算上限（元），超出自动降级 |
| `LLM_PARALLEL_CALLS` | 2 | 独立模型批次并发数；不改变输入与校验，供应商限制并发时可设为 1 |
| `LLM_MAX_OUTPUT_TOKENS` | 2000 | 通用模型输出上限；事件抽取至少使用 8000，避免思考 token 截断 JSON |
| `FISCAL_YEARS_BACK` | 5 | 回看的完整财年数 |
| `ANNOUNCEMENT_MONTHS` | 12 | 公告检索区间（月） |
| `MAX_PDF_DOWNLOADS` | 25 | 单次扫描原文下载份数上限 |
| `SCAN_TIMEOUT_SECONDS` | 900 | 任务超时（秒），超时生成带缺口的部分报告 |
| `PER_HOST_RPS` | 2.0 | 每主机请求频率上限，对数据源保持克制 |
| `ALLOW_PRIVATE_ADDRESS` | false | 保持 false，防 SSRF |

## 工作流程（方案 §4 固定主流程）

```
公司识别 → 检索规划 → 资料获取 → 标准化 → 规则检查 → 专项阅读 → 核验 → 报告生成
```

- **程序负责**：获取与追踪来源、计算指标、执行规则、校验证据引用、管理任务状态、渲染安全 HTML
- **AI 负责**（可插拔）：理解附注与公告、解释已算出的异常、识别缓解因素、独立核验结论与证据的一致性
- 模型不参与任何数值计算；未配置密钥时相关步骤整体跳过并标注，绝无模拟结论
- 相互独立的模型批次默认最多 2 路并行；输入、模型参数、预算、校验和合并顺序保持不变

每条风险按统一结构呈现：

> 发现了什么 → 为什么值得关注 → 证据是什么（原文片段 + 页码 + 指纹）→
> 当前是否仍存在 → 有哪些缓解因素 → 还需核实什么

## 规则体系

共 52 项配置化规则（完整清单、阈值与适用行业见 `docs/RULES.md`）：

- 通用规则 36 项（财务质量 12 / 偿债 8 / 治理 6 / 监管 5 / 经营 5）
- 行业包：银行 4 项、保险 4 项、券商 4 项、地产 4 项
- 每个检查项只输出五种结论之一：发现风险 / 需要关注 / 已覆盖资料中未发现明显异常 / 数据不足，无法判断 / 不适用
- 银行、保险、券商自动跳过不适用的普通企业财务结构规则（资产负债率、流动比率等），
  地产的杠杆判断由"剔除预收后的资产负债率"（RE01）替代普通资产负债率（SV02）
- 严重程度与证据强度分别表达；重要性过滤：应收/存货占总资产 < 2% 时增速类指标不形成结论
- V1.2 起新增能力口径：银行/保险/券商的监管类检查（资本充足率、偿付能力、净资本等）
  数据源未提供字段时标记为"数据源暂不支持"，不计入已执行的有效检查数量，不冒充数据不足

## 报告

- 标题格式：`证券简称（代码）排雷报告`，如"兆易创新（603986.SH）排雷报告"
- 在线阅读：`/report/{task_id}`（与下载内容完全一致）
- 独立 HTML 下载：`/download/{task_id}`——内联 CSS + 内联 SVG 图表，
  无外部脚本/字体/图片依赖，离线可读、可打印；手机端将五列表格转换为带字段标签的卡片，避免缩列和横向滚动
- 响应式布局：PC 保留完整表格；640px 以下优化标题、目录、评分、触控折叠区和卡片间距，360px 以下切换为单列目录与元数据
- 动态文字统一转义，来源链接仅允许 http/https
- 章节结构（4 节，附可点击跳转的报告目录）：
  1. **风险总览**——风险信号评分、结论速览与发现清单
  2. **逐项检查结果**——五个维度逐条结论（"不适用"与"数据不足"行不显示；长说明折叠）
  3. **问题详情与原文**——每条结论的完整证据链（原始证据默认折叠，打印时自动展开）
  4. **数据来源与算法**——AI 参与情况、计算口径与免责声明

### 风险信号评分

- 计算方式：基础分 100，按检查项扣分——发现风险 高-12 / 中-8 / 低-4，
  需要关注 中-2 / 低-1，下限 0；"数据不足"、"不适用"与"数据源暂不支持"不扣分
- 保留醒目的 A—E 风险等级徽章（A 绿 / B 蓝 / C 黄 / D 橙 / E 红），便于快速查看；
  该等级由风险信号评分分档得出，同时展示最高已确认风险、风险关注数量、有效覆盖率与证据复核率
- 计算位置：`app/report/render.py` 的 `risk_signal_score()`（程序计算，模板只展示）
- 免责口径：评分为检查项扣分加权汇总，反映风险信号密度，不代表投资价值或违约概率

## 常见问题

**Q：扫描报网络错误 / 公告获取为 0 条？**
依次检查：本机是否开了系统代理（代理会拦截对数据源的请求，可在终端 `unset http_proxy https_proxy` 后重启）；
数据源接口是否临时变更（查看 `/admin` 页数据源健康状态；
运行 `python scripts/phase0_validate.py` 定位断在哪个环节）。

**Q：提示"已有 60 分钟内的扫描结果"？**
同查询 60 分钟内去重复用。需要重新扫描时在提交页勾选"强制刷新"，或 API 传 `"force": true`。

**Q：报告里大量"数据不足，无法判断"？**
正常设计，不是缺陷。行业监管指标（资本充足率、偿付能力充足率等）当前数据源未提供结构化字段，
按方案要求明确标注而非估算。此类检查项在"逐项检查结果"中不显示（不形成结论），
总数和逐项原因在"风险总览"的折叠清单中汇总。

**Q：如何验证报告里的证据是真的？**
每条证据带文件名、页码和内容指纹，可在"数据来源与算法"一节回溯到原始公告 URL；
程序在生成后还会做一次原文复核（下载文件重新解析比对），复核未通过的会在报告中标注。

**Q：想调整规则的阈值？**
规则定义在 `app/engine/rules/general.py`（通用）和 `app/engine/rules/industry.py`（行业包），
